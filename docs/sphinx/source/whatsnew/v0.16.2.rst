v0.16.2 (Anticipated December, 2026)
------------------------------------

Breaking Changes
~~~~~~~~~~~~~~~~


Deprecations
~~~~~~~~~~~~
* The signature of :py:func:`pvlib.temperature.noct_sam` has changed: the
  first parameter is now ``effective_irradiance``, ``poa_global`` is removed,
  and the remaining optional parameters are keyword-only. Calls using the
  previous signature still work but emit a deprecation warning, and support
  for them will be removed in v0.18.0. (:issue:`1462`, :pull:`2905`)


Bug fixes
~~~~~~~~~
* :py:func:`pvlib.temperature.noct_sam` now calculates cell temperature from
  ``effective_irradiance`` directly, matching the corrected SAM implementation
  (NREL/ssc#1233). Previously the ratio of effective to total irradiance was
  folded into ``transmittance_absorptance``, so reflection losses did not
  reduce the modeled temperature of an open-circuit module, and small ratios
  gave cell temperatures below ambient. (:issue:`1462`, :pull:`2905`)
* :py:func:`pvlib.tracking.calc_surface_orientation` returns scalar when input
  is scalar (:issue:`2881`, :pull:`2882`)

Enhancements
~~~~~~~~~~~~
* Add ``dataset`` parameter to :py:func:`~pvlib.iotools.get_era5`
  allowing for choosing between ERA5 and ERA5-Land datasets.
  (:pull:`2780`)

Documentation
~~~~~~~~~~~~~
* Clarified in :py:func:`pvlib.tracking.singleaxis` that the tracker
  rotation minimizes the angle of incidence (AOI) to maximize the use of
  direct normal irradiance (DNI). (:issue:`2314`, :pull:`2869`)
* Fix the :py:func:`pvlib.spa.solar_position` docstring, which listed
  outputs ``elevation`` and ``apparent_elevation`` in the wrong order.
  (:issue:`2886`, :pull:`2887`)

* Clarify that :py:func:`pvlib.ivtools.sdm.fit_pvsyst_sandia` and
  :py:func:`pvlib.ivtools.sdm.fit_desoto_sandia` require multiple IV curves.
  (:issue:`1715`, :pull:`2883`)
