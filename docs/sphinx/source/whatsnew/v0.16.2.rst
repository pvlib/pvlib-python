v0.16.2 (Anticipated December, 2026)
------------------------------------

Breaking Changes
~~~~~~~~~~~~~~~~


Deprecations
~~~~~~~~~~~~


Bug fixes
~~~~~~~~~
* Correct the Series name in ``ModelChain.results.dc_ohmic_losses`` from
  ``i_mp`` to ``p_dc_ohmic_loss`` when using ``dc_ohms_from_percent``.
  (:issue:`1959`, :pull:`2912`)
* :py:func:`pvlib.tracking.calc_surface_orientation` returns scalar when input
  is scalar (:issue:`2881`, :pull:`2882`)
* :py:func:`pvlib.scaling.wvm` no longer returns all NaNs when ``positions``
  contains a single site (:issue:`2895`, :pull:`2896`)
* Document the URL default :py:func:`pvlib.iotools.get_acis_station_data` actually
  uses. Its docstring named the GridData endpoint; should be StnData.
  (:pull:`2950`)
* :py:func:`pvlib.iotools.read_panond` now detects the encoding of the file
  when ``encoding`` is not specified: UTF-8 if the file starts with a byte
  order mark or is valid UTF-8, otherwise Windows-1252. Previously the
  platform's default encoding was used, so the result depended on the
  operating system's locale. (:pull:`1888`)

Enhancements
~~~~~~~~~~~~
* Add ``pandas==3.1.0`` support. (:pull:`2924`)
* Add ``dataset`` parameter to :py:func:`~pvlib.iotools.get_era5`
  allowing for choosing between ERA5 and ERA5-Land datasets.
  (:pull:`2780`)
* Add :py:func:`pvlib.inverter.ond_to_sandia_inv` to determine parameters for
  :py:func:`pvlib.inverter.sandia` from the content of a PVsyst OND file, and
  :py:func:`pvlib.inverter.extract_inverter_characteristics` to extract the
  efficiency curves and ratings from that content. A ``ValueError`` naming the
  missing OND keys is raised when the file lacks required data.
  Based on work by :ghuser:`cwhanse`. (:pull:`1888`)

Documentation
~~~~~~~~~~~~~
* Fix :py:func:`pvlib.bifacial.power_mismatch_deline` incorrect derivation
  of total RMAD from rear RMAD. (:issue:`2929`, :pull:`2930`)
* Add :py:func:`pvlib.spa.transit_sunrise_sunset` to the API reference.
  (:issue:`2255`, :pull:`2873`)
* Clarified in :py:func:`pvlib.tracking.singleaxis` that the tracker
  rotation minimizes the angle of incidence (AOI) to maximize the use of
  direct normal irradiance (DNI). (:issue:`2314`, :pull:`2869`)
* Fix the :py:func:`pvlib.spa.solar_position` docstring, which listed
  outputs ``elevation`` and ``apparent_elevation`` in the wrong order.
  (:issue:`2886`, :pull:`2887`)
* Link the :py:mod:`pvlib.iotools` module from the FAQ entry on irradiance
  data. (:issue:`1983`)
* Clarify that :py:func:`pvlib.ivtools.sdm.fit_pvsyst_sandia` and
  :py:func:`pvlib.ivtools.sdm.fit_desoto_sandia` require multiple IV curves.
  (:issue:`1715`, :pull:`2883`)
* Note deprecation of ``king`` model in :py:func:`~pvlib.irradiance.get_total_irradiance`
  and :py:func:`~pvlib.irradiance.get_sky_diffuse` docstrings.
  (:issue:`2897`, :pull:`2904`)
